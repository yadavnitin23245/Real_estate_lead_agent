# HomeMatch — GreenKey Realty (Pune)

AI lead agent for a fictional brokerage. Buyers browse listings and chat with an agent
that qualifies them, matches listings, and hands warm/hot leads to human sales agents.

> Work in progress — built in steps. **Done: step 1 (docker-compose, schema, seed data).**
> The full README (architecture, demo script, eval results) comes in step 8.

## Quick start

Each part has its own env file:

```bash
cp backend/.env.example backend/.env      # DB, admin/demo passwords, embeddings, LLM keys
cp frontend/.env.example frontend/.env    # dev-server proxy target
docker compose up --build                 # db + backend + frontend
```

- Frontend: http://localhost:5173 (step 1 shows a status card)
- API health: http://localhost:8000/api/health
- Postgres on your machine: `localhost:5440` (override with `DB_PUBLISHED_PORT=...`)

The `db` service reads `POSTGRES_USER/PASSWORD/DB` from `backend/.env`, so they are set in one place.
On first start the backend creates the schema and seeds the data. The seed downloads the
embedding model (~470 MB, cached in the `hf_cache` volume), and the frontend installs npm
packages into a volume, so the first boot takes a few minutes. Later boots take seconds.

## Database (code-first)

Tables come from the SQLAlchemy models via Alembic migrations. To use any other Postgres
server (it needs the pgvector extension available, e.g. `pgvector/pgvector:pg16`, Supabase, Neon or RDS),
set `DB_HOST/DB_PORT/POSTGRES_*` (or `DATABASE_URL`) in `backend/.env` and run:

```bash
cd backend
python manage.py setup            # create DB if missing + enable pgvector + migrate + seed
python manage.py setup --no-seed  # schema only
python manage.py migrate          # apply new migrations
python manage.py check            # show target server and migration status
```

Inside Docker, prefix with `docker compose exec backend`.
After changing models, run `alembic revision --autogenerate -m "..."` to create a migration.

## Seed data

```bash
docker compose exec backend python manage.py seed           # idempotent: only adds what's missing
docker compose exec backend python manage.py seed --reset   # wipe listings/leads (keeps users) and re-seed
```

- 200 approved listings in 12 Pune localities (150 apartments 1–4 BHK, 12 houses, 10 villas,
  20 plots, 8 commercial units); 20 of them are marked sold. Codes look like `GK-BAN-001`.
- 5 seller listings waiting in the approval queue (`GK-PND-001…005`).
- Descriptions are built from templates (no LLM) and embedded with
  `paraphrase-multilingual-MiniLM-L12-v2` (384 dims, set by `EMBED_DIM`).
- Images are flat illustrations generated by `backend/seed/make_placeholder_images.py`
  (no third-party photos). To use your own CC0 photos, replace the files in
  `backend/seed/assets/` with files of the same names.
- 15 sample leads in mixed states (hot/warm/cold; new → closed), with chats, matches,
  visit requests and cost events.
